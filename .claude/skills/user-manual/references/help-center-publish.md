# 帮助中心发布约定（Platform C Help Center）

> 把 `user-manual-{feature}.md` 发到 Platform C 帮助中心时 Read。源 md 即发布版，发布只做「传图替链 + 必要降级」。

## 一、图片：上传后替换链接

源 md 用相对链接 `images/NN-slug.png`，帮助中心不认本地路径。发布流程：

1. `build_manual.py` 已产 `images-manifest.txt`，列出全部引用图。
2. 按清单把每张图上传帮助中心 CMS 的图床，拿到返回 URL。
3. 把 md 里对应 `images/NN-slug.png` 替换成返回 URL。
4. `alt` 文本（`图：…`）保留——既是图注，也是无障碍/加载失败时的替代文字。

> **【提示】** 不要把 docx 里的图导出再传——直接用 `images/` 里的原图，清晰度一致、可追溯。

## 二、结构降级

帮助中心多数 CMS 吃标准 Markdown，但渲染能力比 docx 弱，按需降级：

- **callout**：源里的 `> **【提示】** …` 是标准 blockquote，帮助中心直接渲染即可，**无需** docx 那套底纹框（`callout.lua` 只作用于 docx，不碰 md）。
- **标题层级**：手册标题块（粗体行 + 元信息表）若 CMS 有独立的标题/副标字段，挪进字段，正文从 `# 欢迎使用` 起。
- **`:::steps` 步骤表格**：源里的 `:::steps` 围栏（多图并排步骤）推 Confluence 走收窄表格；发帮助中心 CMS 时，若 CMS 不支持表格内嵌图，拆成上下多张图各带 caption。
- **附录名词表**：保留两列表；CMS 不支持则降级为「术语 —— 含义」列表。
- **内部文档元信息不进正文**：版本号 / 适用范围 / 更新日期这类给团队内部核对用的元信息块，帮助中心文章是对客发布物，不放这些内部字段——需要留痕挪进 CMS 后台的元数据字段，正文只留用户需要的操作内容。

## 三、一篇 vs 多篇

混合式手册既能整篇发，也能拆：

- **整篇发**：一篇长文，左侧大纲跟 H2 走。适合「一个功能的完整手册」。
- **按任务拆**：每个 `## 如何…` 任务章拆成一篇独立帮助中心文章（动词标题正好做文章标题），互相挂内链。适合功能多、用户按单一目标搜索的场景。
  - 拆分时每篇补一句「前置：先完成《如何 X》」内链，别让用户跳着读断片。
