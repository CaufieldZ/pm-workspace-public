## 二、各段写法要点

**标题动词化**：H2 章节名用「如何/怎么 + 动作」（`如何推策略卡`），别用名词功能块（`策略卡管理`）。帮助中心按用户意图搜索，动词标题更命中、更扫得动。

**四段式**：每个操作任务统一 `前置条件 → 操作步骤 → 预期结果 → 提示与风险`。前置让用户不白忙、预期让用户知道做对没有，这两段是范本最缺、最该补的。

**步骤 ↔ 截图呼应**：有序步骤 `1. 2. 3.` 与截图里的标注角标对应（角标在图上由设计标，正文一律 `1. 2. 3.`，不用圈号）。一张图配一句 `图：` caption 说清画的是哪一步，别一张干图配长段文字。

**callout 四类**（写成 blockquote，docx 自动渲成底纹框）：

| 写法 | 用途 |
|---|---|
| `> **【说明】** …` | 背景 / 能力边界 / 二期预告 |
| `> **【提示】** …` | 顺手的好习惯、可选项 |
| `> **【重要】** …` | 不照做会卡流程 / 出错 |
| `> **【⚠️ 风险提示】** …` | 不可逆 / 对外可见 / 资金相关（交易、推送信号） |

**多图步骤用 `:::steps`**（多图并排 / 两端对比 / 二选一）：

```markdown
:::steps

| 第一步：{语义} | 第二步：{语义} |
| :---: | :---: |
| ![图：{左图}](images/0N-a.png) | ![图：{右图}](images/0N-b.png) |

:::
```

表头写步骤语义（「第一步：点头像｜第二步：点主播中心」「手机端｜电脑端」「立即开播｜预约开播」），推 wiki 图片自动收窄不显大。单张说明图仍走文本流。

**讲人话**（hook 强阻断）：对读者说「你」，动作用祈使句。禁内部场景号（A-1）/ 决策号 / 埋点事件名（`live_start`）/ 字段名 / API 参数。说「点『开始直播』」，不说「触发开播事件」。

## 三、对客文案的语气（去 AI 味 · 正向契约）

领导验收对客手册 / 营销稿的高频吐槽是「AI 味重、像说明书」。讲人话（禁术语）只是及格线，**有温度**才过关。参考成熟交易所的对客教程（币安广场直播教程、Gate Live 帮助、Bitget 开播教程）提炼，好文案由这四块组成：

- **开场用提问钩子 / 场景代入**，不平铺功能：✅「想开一场直播，却不知道从哪一步开始？」「越来越多的交易者正通过直播分享观点」 ❌「本手册介绍直播创建功能」。
- **短句 + 祈使动词**，一句一动作：✅「点击首页头像，进入个人中心」 ❌「用户需要在完成登录后点击位于首页的头像按钮方可进入个人中心」。书面连接词（方可 / 即可 / 通过…来）能删则删。
- **结尾给温度收尾**，不戛然而止：手册末尾（FAQ 后、附录前）加一段感召，如「到这里每一步你都清楚了，剩下的就是创建你的第一场直播——期待在直播间看到你」。营销稿结尾行动召唤同理。
- **克制修饰**：Platform C 调性偏稳，不堆 emoji（币安满屏 💡📌🔥 不照搬），靠句子节奏和直接对话感提温度。合规红线不破：不承诺收益、不用绝对化用语（最 / 第一 / 唯一）。

这四条是「产出形态」契约不是禁令：写完回读，缺开场钩子 / 缺温度收尾 / 句子拖沓 = 没写到位，补。

**截图命名**：`NN-slug.png`，`NN` 两位序号 = 正文出现顺序，`slug` 语义英文短名（`01-workbench-entry.png`）。
