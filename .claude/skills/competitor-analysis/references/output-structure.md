# 竞品分析 · Markdown 输出结构示例

两套结构，按用途选：

- **截图&说明表范式**（推荐，对外汇报 / 给业务方看）：每个功能分区先「每家一句定性」，再「逐平台截图 ＋ 说明与剖析表」，深度写在表格说明列里，一屏看清横向差异。
- **CRBE 深度版**（立项调研 / 战略对标）：完整 CRBE 框架，逐功能拆五层，适合内部深挖。

排版铁律：禁用 `---` 水平分隔线（Confluence 渲染崩），用 `##` 标题或空行分隔；全角标点；打分缺证据标「—」不硬凑。

## 范式 A · 截图&说明表（推荐）

```markdown
# {功能模块} 竞品分析 · {季度}

分析日期：YYYY-MM ｜ 分析人：PM ｜ 档位：深度版

## 〇、我方约束摘要

（从 baseline / profile 提取团队 / 资源 / 用户约束，3-5 行 bullet）

## 一、背景（为什么做这次调研）

**结论先行**：一段话说清我方现状卡点 ＋ 为什么现在看这些竞品。

## 二、竞品选择与分层

**Tier 1 · 直接竞品**

| 平台 | 定位 | 该模块现状 | 素材 |
|------|------|-----------|------|
| {竞品} | 一句话定位 | 现状 ＋ 关键数据 | 截图 N 张 |

**Tier 3 · 跨界参考**（可选）

| 平台 | 看什么 | 素材 |
|------|--------|------|

## 三、功能点打分对比矩阵

先给每家一句话定位（加粗平台名 ＋ 定性判断，领导范式）：

- **{竞品 A}**：一句话定性（最强 / 最朴素 / 激励最激进…）
- **我方**：一句话定性（哪几块第一梯队、哪几块落后）

打分表带「大维度分组列」，1-9 分（先定「9 分长什么样」再打），每维度最强项挂 👍，**缺证据的格标「—」不硬凑**：

| 大维度 | 功能项 | {竞品 A} | {竞品 B} | 我方 |
|--------|--------|---------|---------|------|
| **{大类 1}** | 子项 1 | 9👍 | 6 | 7 |
|  | 子项 2 | 8 | — | 4 |
| **{大类 2}** | 子项 3 | ... | ... | ... |

**打分口径（9 分基准）**：逐维度说清「9 分长什么样」＋ 特殊给分理由。

**证据依据**：哪些分来自截图实证、哪些来自公开文档（标「需验证」）、哪些维度不可比标「—」。

## 四、功能拆解（截图&说明）

按功能分区逐块横向对比，每块结构固定：整体分析（每家一句定性）→ 建议 → 逐平台截图与剖析表。

### 4.1 {功能分区名}

**整体分析**（每家一条，加粗平台名）：

- **{竞品 A}**：这个分区它怎么做、强 / 弱在哪
- **我方**：现状 ＋ 和最优的差距

**建议**：**加粗一句，落到我方具体动作 ＋ 优先级（P0/P1/P2），不接受「可以考虑优化」空话。**

| 平台 | 截图 | 说明与剖析 |
|------|------|------------|
| {竞品} | comp-xx.png（无则标 ⬜ 待贴 ＋ 该截什么） | 设计 ＋ 为什么这么做 ＋ 好 / 差在哪，深度写这里 |
| 我方 | ⬜ 待贴 | 现状 ＋ 差距 |

（4.2 / 4.3 … 同结构，每个功能分区一节）

### 4.N 全市场关键发现 / 我方核心短板

单列跨分区的重结论（如「只有 X 和我方做到 Y」），或直陈我方最关键的根本短板。

## 五、{专题章}（如创作者激励体系）

需要横向深挖的专题单开一章：概览表 ＋ 标杆深挖 ＋ 我方差距。

## 六、可借鉴点 ＋ 我方进度

| # | 可借鉴点 | 来源（章节号） | 我方进度 | 翻车风险 |
|---|----------|--------------|----------|----------|
| 1 | {点} | {竞品}（4.2） | 🔴 未开始 | {直接抄的坑} |

图例：🟢 已上线 / 🟡 开发中 / 🔵 已排期 / 🔴 未开始 / ⚫ 评估后放弃

## 七、后续规划

**先说 N 条最重的结论**：bullet 罗列。

**按优先级 ＋ 前置依赖排的行动建议**（每条动作见对应分区，不重述）：

- **P0 · {行动}**（见 4.x）——一句话收益 / 前置
- **P1 · {行动}**（见 5.x）——…

## 附录

- 截图目录 / 待贴清单 / 数据来源 / 分析局限
```

## 范式 B · CRBE 深度版（立项调研 / 战略对标）

在范式 A 的基础上，功能拆解章改为逐功能拆五层，并补 CRBE 四维 + 反向结论 + 翻车预警。

**单功能五层拆解**：

```markdown
### 2.1 {功能名称}

**模式命名**：一句话给竞品这套打法起个有记忆点的名字（如「交易员闭环」/「实盘竞技场」）
**设计方案**：交互流程、页面结构、信息架构，引用截图
**设计意图**：为什么这么设计、服务什么业务目标、能追问「为什么是 X 不是 Y」的拆一层
**优点 / 缺点**：设计好 / 差在哪
**三角对比**：入口位置 / 交互步骤 / 信息密度 / 核心差异（竞品 vs 基准竞品 vs 我方）
**借鉴价值**：能学什么 ＋ 直接抄的翻车风险
**我方进度**：🟢🟡🔵🔴⚫ ＋ 具体说明
**建议**：加粗一句，落到我方动作 ＋ 优先级
```

**CRBE 四维**（核心章）：

- **C**apability 能力拆解：逐项标 ✅可复制 / ❌不可复制 / ⚠️路径红利 / 💎差异化机会
- **R**oute 路径分析：竞品怎么走到今天、路径依赖是什么、我们能不能走同一条路
- **B**arrier 壁垒识别：网络效应 / 数据积累 / 品牌认知，逐项判断我方能否突破
- **E**fficiency 效率对比：同任务竞品几步、我方几步，转化漏斗各环节差异

**反向结论**：🚫 不该学的 3 件事 ／ 🧩 可借鉴的底层逻辑 ／ 💡 差异化机会。

**翻车预警**：产品 / 用户 / 技术 / 运营 / 成本 五层风险表。

## 通用铁律（两套范式都守）

- 未公开数据不编造，标「未公开，需验证」
- 打分矩阵缺证据的格标「—」，不拍脑袋填分
- 竞品「没有 / 不支持」类断言先查证，别想当然否定竞品价值
- 涉及我方现状的判断回读 baseline / PRD，不凭印象脑补
- 每条可借鉴附翻车风险 ＋ 我方进度
- 反向结论 ≥ 正向结论
