## 一、视频脚本骨架（`launch-{feature}-video.md` · 官方分镜表）

### 黄金三段式 → 30s 死秒锚点

30s 视频按官方死秒（比例仅用于换算非 30s 时长）：

| 段 | 时间（30s） | 作用 |
|---|---|---|
| 开场·痛点钩子 | 0–3s | N 秒内引共鸣，不划走 |
| 中段·核心卖点 | 3–20s | 每镜头一个卖点 |
| 结尾·行动召唤 | 20–30s | 引导马上体验 |

非 30s 时长（如 15s）按比例缩放。卖点数：**中段 3～4 个核心卖点**；15s 短视频受口播字数预算约束（中文口播约 4–5 字/秒）可减到 2～3 个。

### 文案写法要点

- 行标签「开场 / 功能一~四 / 结尾」是官方结构槽位；每个「功能 X」行的**中文文案仍写「功能 + 用户价值」卖点句**（✅「真实成本自动计算，不用手动对账」），≤20 字。
- 结尾镜头官方要求带**Platform CLogo+二维码**，落「中文文案」列括注即可，截图列填「—」。
- 中文文案放旁白（配音念的）或画面文字（屏幕上的），按实际需要写。
- 圈注只放「重点突出」列，标出截图里圈出哪块，无圈注则填「—」。

### 开场钩子写法（合规就地提醒）

提问式 / 痛点式 / 场景式 / 对比式四选一。**只戳体验痛点，不碰行情涨跌与收益**（硬规则 5）：

- ✅「每次都要翻好几页才找到想看的内容？」（找不到 = 体验痛点）
- ✅「想加仓，资金还在现货账户，划转要好几步。」（操作繁琐 = 体验痛点）
- ❌「总是错过暴涨行情？」（暗示抓涨 = 承诺收益，拦）
- ❌「Platform C 上线了 XX 功能。」（直接报功能，不引共鸣）

## 四、海报骨架（`launch-{feature}-poster.md`）

系列海报，1 张总览 + 3 张分述；总览可单投，成组投放按 1 → 2 → 3 → 4 递进。

```markdown
**{产品/功能名} 宣发海报文案**

形态：4 张系列海报（1 张总览 + 3 张分述），交设计侧出图
配图源目录：`./images/`{；本轮无截图时改写为「本轮无 PRD / 原型 / 截图，画面方向见出图说明，交设计侧按线上版本出图」，不要留一个空指向的路径}
卖点池（四形态共用，本文件取以下 3 条）：
- {卖点一，功能 + 用户价值，≤20 字}
- {卖点二}
- {卖点三}

## 海报 1 · 总览

主标题：{功能名} 全新上线
副标题：{用户所处的状态，一句话}
其他内容：
支持：{能力一}、{能力二}、{能力三}
落款：{CTA + Logo / 二维码，单投时必须有}

## 海报 2 · {分述主题一}

主标题：{主题名}｜{四字}，{四字}
副标题：{用户所处的状态或感受}

## 海报 3 · {分述主题二}

主标题：{主题名}｜{四字}，{四字}
副标题：{用户所处的状态或感受}

## 海报 4 · {分述主题三}

主标题：{主题名}｜{四字}，{四字}
副标题：{用户所处的状态或感受}

## 锚位卡（内部，不入画）

- 锚位：海报2主标题 ｜ 关系={六代号之一} ｜ 证据={这句所依据的事实出处，具名} ｜ 专属理由={为什么只有这个功能能这么说}
- 锚位：海报3主标题 ｜ 关系={…} ｜ 证据={…} ｜ 专属理由={…}
- 锚位：海报4主标题 ｜ 关系={…} ｜ 证据={…} ｜ 专属理由={…}

## 视觉规格（内部，不入画）

- 画幅：{四张统一。比例 + 从闭集取一个 --size：1536x1536 / 1280x1600 / 1152x2048 / 2048x1152 / 1536x2048。**不自拟尺寸**——宽高须为 16 的倍数，1080x1920 这类会被 image_gen 直接拒}
- 安全区：{文字避让哪些区域；二维码与落款的净空}
- 文字落位：{主标 / 副标压画面什么位置；四张落位一致；谁是视觉重心}
- 底图来源：{真实截图路径 | 设计侧按线上版本出图}；遮挡：{要遮挡的敏感区，无则写「无」}

## 出图说明（内部，不入画）

{四张的关系 / 配图来源 / 数字口径}
```

「出图说明」三段的写法：

| 段 | 写什么 | 没有素材时怎么写 |
|---|---|---|
| **四张的关系** | 每张主标题与副标题各走哪种关系（用六代号），加一行整组分布；同一种**句式形状** ≥3 次要点名 | — |
| **配图来源** | 三张分述各对应哪一屏真实界面，总览用哪张/什么画面 | 无截图时：写「本轮无截图」+ 各张的画面方向 + 「交设计侧按线上版本出图，不照本文件凭空画界面」 |
| **数字口径** | 引用了哪些数字、各自出处 | 无数字时：明写「本组不含数字」，并点名哪些数字若设计侧要用须先回产品侧核口径（如提醒提前量、跳转路径） |

**要点**：

- 总览主标题是**宣布式**（`{功能名} + 全新上线`），副标题给用户所处的状态。总览可单投，所以落款槽位（CTA + Logo / 二维码）必须完整落在海报 1 上。
- 分述主标题走 **`{主题名}｜{四字}，{四字}` 对仗**——**「对仗」指的是两段之间的关系，不是字数形状**。写「分工 / 位移 / 对照 / 并列 / 在场 / 落点」六种之一（见 SKILL.md §4）；写成顺承（第二段是第一段的必然结果，如「点开就到」）即降档，checker 会拦。
  **形状与关系冲突时，关系优先、字数让路**：为了凑「四字，四字」牺牲信息或把关系写坏，是本末倒置；实际交付里 4+5、5+6、6+4 都能过，checker 只查汉字总数 ≤14。反过来，形状齐整不构成任何保护。
- 字数一律**数汉字，不含标点 / 空格 / 分隔符「｜」**：主标题 ≤14 字、副标题 ≤16 字（海报版面比图文宫格宽）。
- **「支持：」三项**，与三张分述海报的主题一一对应。堆成能力清单 = 没有主次，超过 4 项即降档。
- 副标题只写用户处在什么场景、是什么感受，不写实现方式（见 SKILL.md §4 载体语域契约）。
- **锚位卡**是 `-poster` 的强制内部段：三张分述主标题各一条。`证据`必须具名（PRD 模块 / 功能规格 / 埋点名 / 客诉原话 / 已核口径）——写不出出处就先回去核事实，写「待补证 / 禁止 / 无依据」等同自认不合格，checker 拦；`专属理由`写不出来就说明那句是通用句，回去重写。**副标题也受同一套关系标准约束**（§4 把主标题与副标题都算一句话位置），但锚位卡只强制主标题——副标题的关系逐条写进「出图说明」的「四张关系」里，作为轻量留痕位（不进 checker）。
- 出图说明是内部段落，写清四张关系、配图来源、数字口径，不随图交付。

## 各形态通用写法要点

- **一句话一卖点、≤20 字**：每句只传一个信息点，长了拆。
- **功能 + 用户价值句式**：先写功能，紧跟用户能得到什么。「新增 X」不够，要「新增 X，你就能 Y」。
- **不靠抽象形容词**：更快 / 更简单 / 更方便 / 更省心 / 一目了然这类词换成任何功能都成立，是通用句的配方（判据：抽掉功能名句子仍通顺）。一句话位置改按六种关系写，落点在用户身上，见 SKILL.md §4。
- **讲人话**：内部术语一律翻译。❌「支持 TRTC 实时通信」 ✅「直播延迟低至 1 秒，互动更实时」。
- **合规**：无承诺收益、无绝对化用语（最 / 唯一 / 100% / 稳赚 / 必涨），全形态适用。
- **视觉规格块必填**：`-poster` / `-grid` 四个字段齐（画幅 / 安全区 / 文字落位 / 底图来源与遮挡），`-video` 至少给画幅与安全区，`check_promo_kit.sh` 查。取值与判据见 `promo-visual-spec.md`。**拿不到品牌色与字体就写「按品牌规范，待设计侧确认」**——留一个看得见的待办，别编一个色值把缺口盖住；写「待定」等同没填，checker 拦。
