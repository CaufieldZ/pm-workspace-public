# 宣发物料视觉交付规范（promo-kit）

> 填 `-poster` / `-grid` / `-video` 骨架里的「视觉规格」块前 Read。这份文件回答「交出去的图，版面上要守什么」。
>
> **只定工艺，不定品牌**：品牌主色、辅助色、字体家族由设计侧按现行品牌规范填，本文件不定义、不猜。

**与既有规范的边界**（重合处只给指针，不在这里复述）：

| 文件 | 管什么 | 与本文件的关系 |
|---|---|---|
| `_shared/claude-design/anti-ai-slop.md` | HTML 产出物（原型 / IMAP / PPT）的 CSS 层 | 介质不同：那边是网页，这边是位图投放物料。字号对比、留白、禁全屏渐变几条原则通用，按需去那边读，本文件不复制 |
| `_shared/claude-design/tokens.css` | Anthropic 品牌色板与字体，供工区内部 HTML 产物用 | **与对外宣发物料无关**，别当成宣发品牌色取用 |
| `promo-kit-localization.md` | 图上文字的多语言 String Map | 本文件只管版面，文字内容与语言走那边 |

## 一、投放画幅

按投放位选，不自定非标画幅。右列是 `scripts/image_gen.py` 可直接用的 `--size`（宽高均为 16 倍数、比例与总像素在端点限内，已实测合法）。

| 投放位 | 比例 | `--size` |
|---|---|---|
| 社媒方图 / 4 宫格单格 | 1:1 | `1536x1536` |
| 社媒竖图（信息流主力） | 4:5 | `1280x1600` |
| 全屏竖版（Story / 短视频封面） | 9:16 | `1152x2048` |
| 横版 Banner / 视频封面 | 16:9 | `2048x1152` |
| 海报（印刷 / 长图） | 3:4 | `1536x2048` |

**这五个是闭集，不自拟尺寸**：端点要求宽高均为 16 的倍数，凭印象写的 `1080x1920` / `1080x1440` 都不是（1080 ÷ 16 = 67.5），`image_gen.py` 会在真花钱之前直接拒掉。要别的比例，先用 `python3 scripts/image_gen.py --help` 里的规则换算出合法值再写进产物。`check_promo_kit.sh` 按这个闭集校验。

一组系列物料统一画幅：4 宫格四格同画幅，系列海报四张同画幅。成组投放时画幅一跳，读者会当成两批东西。

## 二、安全区（文字与关键信息的避让）

安全区按**短边百分比**给，跨分辨率通用。各平台若有官方安全区规范以官方为准，下面是通用兜底。

- **四周留白 ≥ 短边 6%**：文字、Logo、二维码都不进这条边，裁切与不同屏幕比例才不吃字。
- **全屏竖版（9:16）三条遮挡带**：顶部 ≥ 12%（系统状态栏与账号信息）、底部 ≥ 18%（平台文案区与操作栏）、右侧 ≥ 12%（互动按钮列）。这三块只放底图，不放任何要读的信息。
- **底图是真实界面截图时**：文字不压在可交互元素上（按钮 / 输入框 / 标签栏 / 底栏）。压上去读者会以为那是能点的。
- **二维码**：四周自带 ≥ 二维码边长 8% 的净空，不压任何图案，不做圆角裁切。

## 三、文字层级与落位

**字阶写相对比，不写绝对字号**——绝对值换个画幅就失效。

- 层级最多三级：主标 / 副标 / 支持项与落款。
- 主标字号 ≥ 副标的 **1.6 倍**，副标 ≥ 支持项的 **1.3 倍**。倍数不够读者分不出主次，整张图变成一段平铺的话。
- 拉不开层级时优先换**字重**而不是继续放大字号，省版面（字体分工原则见 `anti-ai-slop.md` §补 1）。

**落位**：

- 主标压在画面**上三分之一或下三分之一的净空处**，避开界面元素密集区。
- **一张图一个视觉重心**：主标与底图主体不争位，谁是重心在视觉规格块里写明。
- 同组系列物料主标落位一致。成组投放时读者视线不该在四张之间跳。

## 四、底图处理与敏感区遮挡

- **真实截图优先于凭空生图**：文生图会编出产品里不存在的 UI 措辞（把真实的「同意 / 拒绝」编成「通过 / 拒绝」）。产品界面一律以真实截图起步，生图只做增量示意。
- **入画前必须遮挡**：金额 / 余额 / 盈亏数字、真实用户昵称与头像、手机号与 UID、技术状态文字（连接中 / 调试信息）、未上线功能入口。
- **金融宣发额外一条**：任何能被读成收益承诺的数字不入画（对齐 SKILL.md 硬规则 5，画面与文案同一把尺）。
- **同组统一取景**：同一机型、同一场景、同一位主播，只换状态。四张连起来是一条动作线，不是四张功能截图。
- 截图与该格内容对不上就整格不做，不拿别的功能截图硬凑（配图提案的三条边界见 SKILL.md §核心输出规范）。

## 五、可读性下限

- **文字压图必须有底衬**：蒙层、色块或局部模糊三选一。不能靠「那块底图碰巧比较暗」——换张底图就塌。
- 要读的文字最小字号 ≥ 短边 **3.5%**。信息流里图是被缩略着扫过去的。
- 文字与其正下方底色拉开明度差，避开中间调压中间调。

## 六、导出规格

- **格式**：含文字或 UI 截图的用 PNG；纯摄影底图可用 JPEG，质量 ≥ 90。导出一次到位，不在已压缩的图上二次导出。
- **色彩空间**：sRGB。
- **命名**：`{序号}-{slug}[-{lang}].png`，与 md 里截图列逐一对得上。
- **落点**：交付图落 `{项目}/deliverables/assets/`；`image_gen.py` 出的建议稿落 `assets/proposal/`，那是提案不是交付物。

## 七、品牌槽（本文件不定义）

| 槽位 | 谁来填 |
|---|---|
| `{品牌主色}` / `{品牌辅助色}` | 设计侧按现行品牌规范 |
| `{品牌字体}` | 设计侧按现行品牌规范 |
| `{Logo 尺寸与最小净空}` | 设计侧按现行品牌规范；落位见 §三 |

写「视觉规格」块时这三类不猜、不编。没拿到就写「按品牌规范，待设计侧确认」，把它留成一个看得见的待办，别用一个编出来的色值把缺口盖住。
