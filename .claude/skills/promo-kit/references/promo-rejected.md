# 毙句库（promo-kit）

> 与佳作库配套：佳作库记「什么算好」，这里记「什么被判过、为什么」。**价值全在毙因**——同一个坑换个说法会再来一次，认得出毙因才拦得住。
>
> **入库**分两档，来源必须标注：
> - **人类否掉的**（最高价值）——记原话与上下文
> - **判据判掉的**——记命中了哪条判据（顺承 / 机制 / 通用句 / 同义反复）

## 一、人类否掉的

来源：多人连麦海报初版（2026-09-15）。原话：「太土了，太不认真 什么上麦默认静音，海报是这种风格话术吗？？」

| 句子 | 档位 | 毙因 |
|---|---|---|
| 上麦默认静音，准备好了再开口 | **机制** | 写的是产品怎么实现。读者知道了产品怎么工作，不知道自己会落在什么画面里。同一坑的现代变体：把「推送提醒」写成「手机先响」。 |
| 一点申请，开口就聊 | **顺承** | 4+4 齐整，但第二段是第一段的必然结果，零新信息。「申请了就聊上了」不是信息，是定义。 |
| 举手就能上麦，跟主播直接开口聊 | **顺承** | 同一坑，且把功能名正反说了两遍。 |
| 8 位嘉宾，同时在麦 | **系统状态** | 落点在系统（「在麦」是位置），不在人。同样的数字换个落点就成了好句：「八位嘉宾，各抒己见」。 |
| 多人讨论、主题问答，一场都能开 | **通用句** | 抽掉功能名后任何「多功能场景」都成立。场景枚举本身没错，错在枚举完没有落到这个功能独有的事上。 |
| 上麦不打断，一屏搞定 | **通用句** | 「一屏搞定」是套话，任何「不跳转」的功能都能说。 |
| 聊天送礼看行情，上麦期间照旧可用 | **通用句** | 「照旧可用」是维护语（说明系统没坏），不是用户价值。同一句改成「看盘、发言、送礼，一样不少」就成立——**信息没变，落点变了**。 |

## 二、判据判掉的

来源：无指引对照实验（n=5，同一功能）。**这一节最有用的地方是暴露了同一个坑有多种伪装。**

### 顺承——最会伪装的坑

| 句子 | 为什么它看起来没问题 |
|---|---|
| 点开就到，不必再找 | 有对仗、有节奏，读起来像海报字。**实测有产出把它当合规范例引用**，也有产出正确否决——同一条规则判出相反结论，这正是它需要机械兜底的原因。 |
| 点开提醒，你就在现场 | 把「人就到了」改成「你就在现场」——**换了措辞，没换关系**，仍是顺承。有产出以为改对了。 |
| 提醒一响，人在现场 | 画面感强、口语、无术语。但「响 → 在现场」是因果链，第二段没带来新信息。 |
| 一次点选，一场不落 | 「一场不落」还叠加了绝对化擦边。 |
| 一点就进，不用再找 | 双否定看着像「并列」，其实后半是前半的结果。 |
| 先订上再走开 | 「先…再…」是时间顺序＝顺承的显式形态。 |

**共同点**：第二段要么是第一段的结果，要么是第一段的同义改写。**判法**：把第二段遮住，只读第一段——如果读者已经知道第二段要说什么，就是顺承。

### 同义反复——顺承的近亲

| 句子 | 毙因 |
|---|---|
| 想看哪场，就约哪场 | 两段是同一件事的两种说法。比顺承更空：顺承至少有个先后，这个是原地打转。 |
| 刷到的是直播，不是回放 | 两半是同一主语的肯定与否定，「是直播」已蕴含「不是回放」。换成两个独立对象才成立（「回放一直在，开播不重来」）。 |

### 通用句——最难自己发现的坑

| 句子 | 毙因 |
|---|---|
| 稳健入门 / 一目了然 / 清清楚楚 | 抽象形容词。抽掉功能名后任何功能都成立。 |
| 错过直播这件事，到此为止 | 对仗工整、语感不差，「到此为止」还有收束感——但任何「别错过 / 提醒类」功能都能这么说。**工整的通用句比粗糙的通用句更危险**，因为它看起来像好句。 |
| 喜欢的主播，一场都不落 | 通用 ＋ 绝对化擦边。 |
| 从错过到赶上，只差一个提醒 | 位移骨架对了，但「一个提醒」把落点拉回产品能力；对照佳作「从旁观到开口，只差一次举手」——差别在「举手」是用户动作，「提醒」是系统动作。 |

## 三、怎么用这一节

1. **写之前扫一眼**：尤其「顺承」那组——它是最高频的坑，且在因果型卖点（直达 / 一键 / 秒到）上几乎必然触发。
2. **判降档之后回来登记**：新判掉的句子按「别人会不会以为它没问题」的标准决定要不要收——**看起来没问题的才值得收**，一眼假的不用记。
3. **别拿这里的句子当反面模板去改写**：毙因才是可复用的，句子不是。把「点开就到」改成「点开即达」没有任何意义。
