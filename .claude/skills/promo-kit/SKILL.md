# Launch Copy — 上线宣发内容（视频脚本 / 图文 4 宫格 / 短文案）

## 触发与定位

**做什么**：把一个功能/活动写成对外宣发内容。四形态 + 一个渠道变体共享一份卖点池 + 同一套「痛点 → 卖点 → CTA」哲学：

- **视频脚本**（`launch-{feature}-video.md`）：视频 / gif 逐镜头分镜表，一列中文文案（旁白或画面文字）+ 多语言截图列。
- **图文 4 宫格**（`launch-{feature}-grid.md`）：4 张图各承一个卖点，主标 + 副标。
- **海报文案**（`launch-{feature}-poster.md`）：4 张系列海报（1 总览 + 3 分述），主标题 + 副标题 + 支持项，交设计侧出图。
- **短文案**（`launch-{feature}-copy.md`）：标题 + 中段卖点 + 结尾 CTA + 品牌 Tag。
- **WP 发布版**（`launch-{feature}-wp-{lang}.md` · 渠道变体）：发 Platform C Square 博客的正式版，frontmatter 带发布元信息、全篇禁 emoji；中英俄三语一组（`-wp-zh / -en / -ru.md`），`wp_publish.py` 一条命令齐发。

**何时触发**：用户说「宣发脚本 / 视频脚本 / gif 脚本 / 分镜 / 图文宣发 / 4 宫格 / 宣发文案 / 卖点文案 / 海报文案」，或给一个功能要做上线宣发。

**不做**：
- 操作 / 使用手册、帮助中心文章 → 走 user-manual skill（教用户怎么操作，不是宣传卖点）。
- **渠道分版长文案**（Banner / 官方博客长文 / 更新日志条目）→ 走 user-manual skill 的 `promo-` 模式。本 skill 只做上线宣发四形态的短平快交付。
- PRD / 需求文档（内部行为规格）。

**受众**：读者是 **C 端用户 / 潜在用户**，不是研发、不是内部。全篇用户视角、业务白话。

## 硬规则（FAIL 即拦）

1. **落点在用户身上，不写"我们新增了什么"**：每句读完，读者知道的是**自己的处境变了**，不是产品多了一个能力。❌「新增 AI 总结」 ✅「AI 帮你秒懂市场热点」。禁"新增 / 支持 / 优化 / 升级"堆砌。**不靠抽象形容词**——「更快 / 更省心 / 更方便 / 稳健 / 一目了然」这类词换成任何功能都成立，是通用句的配方（判据见 §4「可替换性」）。品牌可用第一人称作为关系的一方（「时间我记，你只管来」落点仍在用户），本条禁的是落点滑到产品，不是禁"我"。
2. **痛点 → 卖点 → CTA，不按功能逐项列**：开场先戳痛点场景引共鸣，中段每个卖点回答「解决什么问题」，结尾引导马上体验。禁**正文开场**直接报功能名（「XX 功能全新上线」开讲）。骨架里标注为宣布式的标题槽位（海报总览主标题、短文案标题）不受此限——那里宣布就是它的职责。
3. **一句话一个卖点、字数上限是体检项不是写作目标**：每句只传一个信息点。卖点句、图文副标 ≤ 20 字；图文主标 8～10 字；海报主标题 ≤ 14 字、副标题 ≤ 16 字。**字数一律数汉字，不含标点 / 空格 / 分隔符「｜」**。先写清楚再收短——先定长度往格子里塞，塞出来的是凑字句；为了压字数砍掉比喻，句子就变成了谜语。
4. **讲人话**（`check_promo_kit.sh` 拦）：禁内部术语 / 技术名 / 场景号（A-1）/ 埋点事件名 / 字段名 / API / 内部迭代版本号（如「社区 3.2」）。❌「支持 TRTC 实时通信」 ✅「直播延迟低至 1 秒，互动更实时」。
5. **金融宣发合规红线**（硬拦 · 比通用营销更严）：
   - **无承诺收益**：禁「稳赚 / 必涨 / 抓住暴涨 / 收益翻倍」等暗示盈利的表达，痛点钩子也不例外（❌「总是错过暴涨行情？」）。
   - **无绝对化用语**：禁「最 / 第一 / 唯一 / 100% / 永久」等。
   - 痛点钩子可写「操作繁琐 / 找不到 / 反应慢」这类**体验痛点**，不碰行情涨跌与收益。
6. **视频节奏 30s 死秒锚定官方**：黄金三段式开场 0–3s / 中段 3–20s / 结尾 20–30s（指南硬约束），非 30s 时长按比例缩放；中段 3～4 个核心卖点，受口播字数预算约束，禁 15s 硬塞 4 个（15s 可减到 2～3）。
7. **命名前缀 `launch-` + 形态后缀**：`launch-{feature}-video.md` / `-grid.md` / `-poster.md` / `-copy.md` / `-wp-{lang}.md`，落 `{项目}/deliverables/{季度}/{版本}/`（无此结构则落用户指定目录）。

## 核心输出规范

### 一份卖点池，四形态复用

先从信源提炼 **2～4 个核心卖点**（`功能 + 用户价值` 句式，每条 ≤ 20 字），四种形态都从这一份池子取，不各写各的。卖点数随载体缩放：

| 载体 | 卖点数 | 依据 |
|---|---|---|
| 视频 30s | 3～4 | 中段 3～20s 每镜头一个卖点 |
| 视频 15s | 2～3 | 口播字数预算（中文口播 ~4–5 字/秒 → 15s 约 60–75 字，含钩子 + CTA 塞不下 4 句卖点） |
| 图文 4 宫格 | 4（不足则 2～3） | 一图一卖点 |
| 海报 | 3 | 1 总览 + 3 分述，总览的「支持：」三项与三张分述主题一一对应 |
| 短文案 | 2～4 | 中段每条聚焦一个信息 |

### 载体语域契约（同一份卖点池，进不同载体换语域）

每个位置写什么，按下表取。**一句话位置**——视频开场、图文主标、海报主标题与副标题、短文案标题——只写「用户处在什么场景、是什么感受」，读者读完知道自己会落在什么画面里；实现方式（默认静音 / 席位 / 排队 / 审批 / 上限）是正文类载体的料，留给短文案中段与 Square 卖点列表。

| 载体 · 位置 | 读者此刻 | 这一块写什么 | 范例 |
|---|---|---|---|
| 视频 · 开场（0–3s） | 手指悬在划走上，还没决定要不要看 | 观众自己的处境，一句话引共鸣 | 「想跟主播聊两句，打字发出去就被刷走了？」 |
| 视频 · 功能行 | 决定看下去了，在等一个值得留下的理由 | 功能 + 用户价值，≤20 字 | 「举手就能上麦，跟主播直接开口聊」 |
| 视频 · 结尾 | 看完了，在想要不要动 | 价值总结 + 行动召唤 | 「举个手就能上麦，打开Platform C App 进直播间试试！」 |
| 图文 · 主标 | 在信息流里滑，一眼扫过 | 一个卖点的短名，8～10 字 | 「举个手，就能开口聊」 |
| 图文 · 副标 | 停了一下，在判断这条跟自己有没有关系 | 该卖点替用户省掉了什么，≤20 字 | 「不用挤在评论区，直接跟主播说」 |
| 海报 · 主标题（分述三张） | 路过投放位，**没有上下文，只看得到这一张** | 功能名｜它带给用户的身份或状态 | 「举手上麦｜你的问题，主播听得见」 |
| 海报 · 主标题（总览那张） | 看到整组里的第一张，要知道这是什么 | **宣布式**：功能名 + 全新上线（硬规则 2 豁免这一格） | 「多人连麦 全新上线」 |
| 海报 · 副标题 | 被主标题留住了半秒，在找理由继续看 | 用户身处什么场景、是什么感受，≤16 字 | 「弹幕会刷走，声音不会」 |
| 海报 · 支持项 | 想确认这功能到底覆盖什么 | 能力三项并列，与三张分述主题对应 | 「举手上麦、多人同台、边聊边看」 |
| 短文案 · 标题 | 和一堆条目并列在列表 / 推送里，半秒决定点不点 | 主题 + 功能名 | 「Platform C直播多人连麦上线，举手就能开口聊」 |
| 短文案 · 中段 | 点进来了，在看值不值得试 | 功能 + 用户价值，一条一信息 | 「举手就能上麦，直接跟主播开口聊。」 |
| 短文案 · 结尾 | 读完了，在等一个动作指令 | 价值总结 + CTA + 品牌 Tag | 「…立即打开Platform C App 进直播间举手…#Platform C进化论」 |
| Square · 导语 | 从站内别处跳进来，还不知道这是什么 | 第三人称陈述：宣布 + 核心价值 | 「示例直播间的互动不再只有文字。多人连麦已经上线…」 |
| Square · 卖点列表 | 已经知道大概，在核具体能力 | 功能 + 用户价值，裸列表 3～4 条 | 「举手就能上麦，直接跟主播开口聊。」 |

「读者此刻」这一列不是修辞——它决定句子能有多长、能不能带前提。**海报主标题那一格最苛刻**：读者没有上下文、看不到别的三张，所以它必须自己站住。这正是「可替换性」判据的物理来源。

### 一句话位置：六种关系 + 两条降档标定

一句话位置的合格形态，是两段之间构成下面六种**关系**之一。关系不是字数形状——「四字，四字」只是外形，写的是什么关系才是这句成不成立的地方。

| 代号 | 关系 | 例 |
|---|---|---|
| 分工 | 谁做什么，拆给两方 | 你忙你的，到点喊你 ／ 时间我记，你只管来 |
| 位移 | 从 X 到 Y，位置变了（两端是用户自己的两种状态，不是「动作 → 到达」） | 从旁观到开口，只差一次举手 |
| 对照 | 旧状态与新状态并置（常省略共同谓语） | 弹幕会刷走，声音不会 ／ 开播时间说不准，提醒不会漏 |
| 并列 | 两件独立的事，互不派生 | 行情不切，对话不断 ／ 看盘、发言、送礼，一样不少 |
| 在场 | 句子里有第二个人 | 你的问题，主播听得见 ／ 举个手，主播就听见 |
| 落点 | 数字后面接人的动作，不是系统状态 | 八位嘉宾，各抒己见 |

**按卖点语义选关系**：卖点的语义决定它最容易掉哪个坑，也就决定该往哪个关系改——因果型（直达 / 一键）→ 位移；委托型（提醒 / 代管）→ 分工；并行型（不影响 / 同时可用）→ 并列；数量型（N 位）→ 落点；状态型（多人 / 同台）→ 在场；感受型（不慌 / 从容）→ 对照。完整对照表与实测例句见 `references/promo-copy-quality.md`。

归类拿不准是常态（「一键预约」既像委托又像因果），**这是取关系的提示，不是分类考试**：拿不准就两类各写一版，取更好的那句。

**单句形态的一句话位置**（副标题常写成一句，如「不用再翻列表找入口」）：六种关系的定义都预设「两段之间」，单句套不进去——**不强行归类**。判据换成两条，都过即合格：

1. **专属**：抽掉功能名还成立吗？成立即降档（可替换性判据）。
2. **有画面**：读者读完知不知道自己在什么场景里？不知道即降档。

出图说明里它的关系栏写「单句 · 专属」即可，不要硬塞一个六代号。

**两条降档标定**（不装进六种里，单独记住）：

- **顺承**——第二段是第一段的必然结果。「点开就到」「一点就进」形状上四字对四字样样齐全，关系上第二段没带来任何新信息。改措辞没用：「点开提醒，人就到了」改成「点开提醒，你就在现场」仍是顺承，得**换关系**。
- **机制**——写产品怎么实现（默认静音 / 席位 / 排队 / 审批 / 上限）。读者知道了产品怎么工作，不知道自己会落在什么画面里。这类词是正文类载体的料，留给短文案中段与 Square 卖点列表。

**可替换性**（自检判据）：把功能名抽掉，这句话还成立吗？成立 = 通用句 = 任何功能都能用 = 降档。「稳健入门」「一目了然」「一点申请，开口就聊」抽掉功能名后照样通顺，所以它们对任何功能都不构成信息。唯一例外：**当"为某类人设计"本身就是卖点时**（模拟盘对新手说「新手友好」），通用是刻意的，不判降档。

**锚位卡**（`-poster` 强制 · 其余形态建议）：三张分述主标题各一条，格式固定——

```
- 锚位：{哪一句} ｜ 关系={六代号之一} ｜ 证据={这句所依据的事实出自哪} ｜ 专属理由={为什么只有这个功能能这么说}
```

三个字段各有分工，缺一不可：

- **关系**写六代号之一；写「顺承」的 `check_promo_kit.sh` 直接拦下。
- **证据**是这句所依据的事实来源，必须具名（PRD 模块 / 功能规格 / 埋点名 / 客诉原话 / 已核口径）。**句子里的每个论断都要能追到一个出处**——写不出出处，就先回去把事实核清楚，别写进产物。写「待补证 / 禁止 / 无依据」等同自认不合格，checker 也拦。
  **只有 Step 0 输入、没有 PRD 时**（Step 1 允许这种起步）：证据写 `本批输入·{输入名}（{原文关键短语}）`，并**显式标注信源等级**——输入是需求方口述，不是核过的规格。同时在「出图说明」留一行事实待核口径，点名哪些数字/路径上线前须按规格复核。**不许编 PRD 模块名或埋点名**：那是把「没核」写成「核过」，比空着更糟。
- **专属理由**写不出来，就说明这句是通用句，回去重写。

> 为什么单列证据槽：只校验「专属理由非空」时，**空口的专属理由照样过闸**——机器分辨不了真假。加上具名出处这一格，模型至少得先找到事实才能落笔；查不出出处是能被抓住的，编得圆不圆是抓不住的。

### 视频脚本骨架（`-video` · 官方分镜表）

黄金三段式（30s 死秒锚定官方，非 30s 按比例缩放）：

| 段 | 时间（30s） | 作用 |
|---|---|---|
| 开场·痛点钩子 | 0–3s | 引共鸣，不划走（提问/痛点/场景/对比式） |
| 中段·核心卖点 | 3–20s | 每镜头一个卖点，答「解决什么问题」 |
| 结尾·行动召唤 | 20–30s | 引导马上体验（体现价值，不止「立即更新」）|

分镜表列（逐字照官方评审模板）：`中文文案 | 重点突出（将中文截图内需要突出的内容圈出） | 截图（中文） | 截图（英文） | 截图（俄语）`（语言列可配）。行标签 `开场 / 功能一~四 / 结尾·CTA`，**结尾镜头带Platform CLogo+二维码**。完整骨架 + 示例见 `references/promo-kit-templates.md`。

**落成片子（可选 · 分镜定稿后）**：分镜表的逐镜头中文文案是给人看的宣发脚本，不是生成模型的提示词。要出真实视频时，把镜头文案按 MiniMax H3 官方结构改写成提示词（分镜 `[Shot N]` / 运镜 / 对白 `<d>` / 音效字段），命令与写法要点见 `python3 scripts/video_gen.py --help`，完整规范与示例见 `references/h3-prompt-writing/`；图生视频可先用 image_gen 出一帧当 `--first-frame`，产物用 `-p {项目}` 落 assets。

### 图文 4 宫格骨架（`-grid`）

4 张图，每图一卖点，风格统一、阅读顺序自然。每格：`主标（8-10 字）+ 副标（≤20 字）+ 配图说明`。骨架见 templates。

图文形态出两块产物：**4 宫格 md 规格**（上面那张表）+ **配图提案**（版面建议稿，给设计侧）。

配图提案：拿得到真实场景截图时，逐格用该格 `配图说明` 当提示词、真实截图当参考图，出 4 张建议稿——

```bash
python3 scripts/image_gen.py "<该格配图说明>" --edit <真实截图> --size 1536x1536 --quality high -p {项目} --out proposal/grid-{n}.png
```

命令可能被权限系统按「数据出域」拦下（`--edit` 会把截图原图字节发给外部端点）——被拦就如实告知用户、等其授权后按原命令补跑，不要改用别的路子绕。

提案落 `deliverables/assets/proposal/`。三条边界：**① 不是交付物**——不登记进「配图索引」/ 截图列、不推 wiki，最终图仍由设计侧按真实截图产出；**② 必须 `--edit` 真实截图起步，且截图要与该格内容对得上**——凭空生图出来的产品界面没有参考价值，拿对应功能的截图，没有就整格不做、不拿别的功能截图硬凑；**③ 交设计侧前人工过一眼**——模型对「去掉批注」这类显式否定指令不可靠，PRD 场景号（如 `→ G-1`）可能残留在提案里。

### 海报骨架（`-poster`）

4 张系列海报：总览 1 张（宣布式主标题 + 状态副标题 + 「支持：」三项），分述 3 张（`{主题名}｜{四字}，{四字}` 对仗主标题 + 状态副标题）。总览的「支持：」三项与三张分述主题一一对应，不堆能力清单。骨架与要点见 `references/promo-kit-templates.md` §四。

### 短文案骨架（`-copy`）

- **标题**：一句话点明主题，可用「全新上线 / 正式发布」，突出功能名。
- **中段**：2～4 条卖点，每条 `功能 + 用户价值`（✅「十几笔加仓减仓，真实成本替你归到一条线」，❌「盈亏明细一目了然」——后者抽掉功能名照样成立）。
- **结尾**：价值总结一句 + CTA（打开 App / 前往某页 / 立即体验）+ **品牌 Tag（必加）**。

品牌 Tag 按团队配置（Platform C 示例：中文 `#Platform C进化论`、英俄 `#Platform CEVOLVE`），配法见 localization。

### 视觉规格块（`-poster` / `-grid` 四字段强制 · `-video` 给画幅与安全区）

文案定「说什么」，视觉规格定「交出去的图在版面上守什么」。四个字段写进产物内部段，`check_promo_kit.sh` 查：

- **画幅**：按投放位取标准画幅并附 `image_gen.py` 可用的 `--size`；一组系列物料统一画幅。
- **安全区**：文字与二维码避让哪些区域；文字不压按钮 / 输入框 / 底栏这类可交互元素。
- **文字落位**：主标与副标压画面什么位置、谁是视觉重心；同组四张落位一致。
- **底图来源 + 遮挡**：真实截图优先于凭空生图；金额 / 昵称 / UID / 技术状态文字入画前点名遮挡，确实没有写「遮挡：无」。

画幅表、安全区百分比、字阶比与导出规格见 `references/promo-visual-spec.md`。**品牌色与字体本 skill 不定义**——没拿到就写「按品牌规范，待设计侧确认」，留一个看得见的待办，别编个色值把缺口盖住。

## 执行步骤

### Step 0 — 定形态 + 收齐 4 个输入
先确认要哪种形态（视频 / 图文 / 海报 / 短文案，可组合）。起草前必须拿到 4 个输入（AI 替代不了前两个的判断）：
1. **功能描述**（一句话）
2. **用户痛点**（具体场景，不是「体验不好」）
3. **核心卖点**（1～3 条，`功能 + 用户价值`）
4. **视频时长**（15s / 30s，仅视频形态需要）

缺痛点或卖点先反问用户，别凭空编。

### Step 1 — 读信源 + 找行业锚

有 PRD / 原型则并行 Read 抓功能事实与页面流程；没有就用 Step 0 的 4 个输入起草。截图 / Wiki 文档亦可作信源——多模态直接看图，从界面反推卖点与分镜（哪屏对应哪个卖点镜头）；**只认截图真实可见的元素，推不出的别脑补、问用户，不为凑镜头硬编卖点**（硬规则 5 / 缺卖点不凭空造）。信源里的内部术语/版本号一律翻成用户白话（硬规则 4）。

**找行业锚**：分两级，**常驻库优先，网络检索是补充**。

1. **常驻佳作库**（必读）：`Read references/promo-copy-quality.md` 的「佳作库」与「喜好 / 禁区」两节。库里是**已验证过的好句**、按关系归类、每条标注为什么生效——这是「什么算好」的正面答案，也是唯一不会失效的锚。
2. **网络补充**（可选 · 期望值放低）：想看同类功能在头部平台（Binance / OKX / Gate / Bitget）的官方宣发，**借关系与场景枚举法，不借内容**。**这条路的常态就是走不通**——交易所的功能级对外海报文案基本不公开，检索命中的多是运营手册与帮助中心页。试一次即可，不成就过，**在交付里一句话写明"本轮无外部锚"**（静默跳过会让人以为锚过了）。功能事实一律以本方 PRD 为准。

**锚只解决语感与关系，不解决水位**：参照物本身可能只是「合格」。抄它的格式时，别把它的语域一起抄进来——先按 §4 判据过一遍，够不上六种关系的句子不进产物。

### Step 2 — 提炼卖点池 + 定连接点

先从信源提炼 2～4 个核心卖点，写成 `功能 + 用户价值` 短句（≤20 字）。这份池子四形态共用。逐条自检：是不是站用户收益角度？有没有暗示收益/绝对化（硬规则 5）？

**再定连接点——起草前必走，别跳过直接填骨架。** 给每个要写的一句话位置选一个连接点，取自五类：

| 连接点类型 | 问自己 |
|---|---|
| 专有名词 | 这件事有没有一个只有它才有的名字或身份？ |
| 核心动作 | 用户做的哪个动作是整件事的支点？ |
| 关键属性 | 哪个属性是别处没有的？ |
| 数字 | 有没有一个数字本身就是信息？ |
| 场景 | 它落在用户生活的哪个具体时刻？ |

**否决门**：五类一个都对不上 → 这个卖点还没有可写的连接点，**换角度或换卖点，不许硬蹭**。硬写出来的必是通用句。

连接点定「写什么」，§4 的六种关系定「怎么搭」。两者配对使用——例：连接点是核心动作「举手」，配位移（从旁观到开口）或在场（主播听得见）；连接点是数字「八位」，配落点（八位嘉宾，各抒己见）。

### Step 3 — 按形态写 md
- **视频**：按 templates 官方分镜骨架写（5 列 + 行标签 开场/功能一~四/结尾），30s 死秒锚定官方、非 30s 按比例换算，卖点数按时长（§4），结尾带Platform CLogo+二维码。
- **图文**：4 宫格，一图一卖点，主标 8-10 字 / 副标 ≤20 字。写完 md 后按 §核心输出规范 的「配图提案」出建议稿（有真实截图时）。
- **海报**：1 总览 + 3 分述，按 templates §四 骨架写。总览主标题宣布式、副标题给状态、「支持：」三项与三张分述对应、落款槽位带 CTA；分述主标题走 `{主题名}｜{四字}，{四字}` 对仗。**三张分述主标题各配一条锚位卡**（§4），写完一并出「出图说明」段（四张关系 / 配图来源 / 数字口径）。
- **短文案**：标题 + 中段 + 结尾三段，结尾必带品牌 Tag。

四形态写完补「视觉规格」块（`-poster` / `-grid` 四字段齐，`-video` 至少给画幅与安全区），取值见 `references/promo-visual-spec.md`。

多语言版 / 品牌 Tag / 图上文字 → 先 Read `references/promo-kit-localization.md`。

### Step 4 — 自检 + 改稿

```bash
bash scripts/check_promo_kit.sh {项目}/deliverables/{季度}/{版本}/launch-{feature}-video.md
```

**机械自检只拦形状，不判质量**——checker 全绿 ≠ 文案能用（「一点申请，开口就聊」曾通过全部检查）。绿了之后再逐句过一遍质量：

1. **锚位卡填得出来吗**：每个一句话位置，`关系`、`证据`、`专属理由` 都写得出？写不出 `专属理由` = 通用句，重写这句；写不出 `证据` = 这句里的事实没核过，先回去核。
2. **三条硬失败**（命中即重写，不是微调）：**顺承**（第二段是第一段的必然结果）、**机制**（写了产品怎么实现）、**通用句**（抽掉功能名句子照样成立）。
3. **改稿预算**：最多重写 2 轮。2 轮后仍有不达标的句子，**带失败项交付并逐句点名**，不要为了收工把失败项说成通过。

> 语感上拿不准时，回 `references/promo-copy-quality.md` 的佳作库对一眼——比再读一遍规则有用。

### Step 5 — 发布到 Platform C Square（WordPress · 可选）

**Step 5a 写 `launch-{feature}-wp-{lang}.md`（发布预览版，中英俄各一篇）**：check 全绿、用户要发布才写。frontmatter 承载全部发布元信息，正文所见即所得（骨架见 templates §五；分类三语对照与站点画像见 `references/wp-square-api.md`，发布前 Read 免重新探测）：
- **全篇禁 emoji**（含 ✅🚀；站内正式文风抽样 9/9 零 emoji，标题可用感叹号）
- **公告体**：头图 + 导语段 + 3～4 条卖点裸列表 + 结尾 CTA 段，不设小标题，300～800 字
- 4 宫格宣发改「段落配图」循环体；视频作尾部 video 块嵌入，不发分镜脚本本身

**Step 5b 用户确认预览后发布**（三语一条命令齐发，篇间自动留间隔、429 自动重试）：
```bash
python3 scripts/wp_publish.py launch-{feature}-wp-*.md
```
- **默认建草稿**返回编辑 / 预览链接；`--publish` 显式才直发（金融宣发合规审校先行）。
- **`lang` 必给**（frontmatter；zh / en / ru / ur）：缺省站点按默认语 en 落库，中文 / 俄文分类会被 Polylang 服务端重映射成英文。
- 分类用站内三语现成名（中「产品更新 / 平台活动 / 市场观察…」· 英 `Product Updates…` · 俄 `-ru` 系列）；不存在报错不自建，标签缺失自动建。
- 多语言三件套 = 每语言一篇 `-wp-{lang}.md`（lang + 对应语言分类 + 语言版封面；站内头图 CN- / RU- 前缀惯例）。**三帖互链 REST 做不了**（Polylang 免费版不暴露 translations，实测写入被忽略）——需互链时 wp-admin 编辑页 Polylang 语言面板手动关联，或接受三帖独立（各语言树内正常展示）。

## 错误处理

- **输入缺失**：Step 0 若用户未给「用户痛点」或「核心卖点」，停止起草、向用户反问具体场景，不得凭空编造。
- **形态不明确**：用户未指定形态时，列出四形态（视频脚本 / 图文 4 宫格 / 海报文案 / 短文案）让用户选，不默认输出全部。
- **自检 FAIL**：`check_promo_kit.sh` 返回非 0 时，按输出的 ✗ 行逐条修，修完重跑，直至 exit 0 方可交付。合规红线（承诺收益 / 绝对化用语）命中一律改写，不豁免。
- **信源含内部术语**：PRD / 原型里的技术名、版本号、场景号一律翻成用户白话再写入，禁原样搬运。
- **发布报网络不通**：按 `.claude/runbooks/proxy-fallback.md` 排沙箱与 Clash（square.example.com 直连不通，必须代理）；凭据缺失看 `.env` 三件套（应用密码含空格，值必须加双引号）。
- **发布报分类不存在**：换站内三语现成名重试，禁自建分类（Polylang 体系防脏）。
- **发布报 HTTP 429**：WordPress.com REST 节流（连续建帖过快触发），等 30～60 秒重试即可。

## 自检清单

`check_promo_kit.sh` 跑完，逐条确认：

- [ ] 全篇落点在用户身上，无「新增/支持/优化」堆砌，无抽象形容词充数（更快 / 更省心 / 一目了然）
- [ ] 结构是痛点 → 卖点 → CTA，正文开场没直接报功能名
- [ ] 每个卖点一句话、≤20 字（图文主标 8-10 字、海报主标题 ≤14 字 / 副标题 ≤16 字；数汉字不含标点）
- [ ] 每个一句话位置按 §4 六种关系写，**无顺承、无机制、无通用句**（抽掉功能名句子仍成立即通用句）
- [ ] Step 2 走过「连接点」，且对上五类之一；一个都对不上时换了角度，没硬蹭
- [ ]（海报）三张分述主标题各带锚位卡，关系取值在六代号内、`证据`具名、专属理由非空
- [ ] 句子里每个论断都能追到具名出处（PRD 模块 / 功能规格 / 埋点名 / 客诉原话 / 已核口径）；追不到的回去核事实，不写进产物
- [ ] 各位置按 §4 载体语域契约写：一句话位置没有滑成实现方式（「默认静音 / 排队 / 审批」这类机制不上开场、主标、海报主副标题、短文案标题）
- [ ] 无内部术语 / 技术名 / 场景号 / 埋点名 / 内部版本号（checker 绿）
- [ ] 金融合规：无承诺收益、无绝对化用语，痛点钩子不碰涨跌收益（checker 绿）
- [ ] 视觉规格块四字段齐（画幅 / 安全区 / 文字落位 / 底图来源），无 `{占位}` 与「待定」；`-video` 至少给画幅与安全区
- [ ] 底图敏感区已点名遮挡（金额 / 昵称 / UID / 技术状态文字），确实没有的写「遮挡：无」；品牌色与字体未编造
- [ ]（视频）官方 5 列 + 截图列在场；30s 死秒 0–3/3–20/20–30；结尾带Platform CLogo+二维码；卖点数匹配时长
- [ ]（图文）4 格风格统一、逻辑连贯
- [ ]（海报）4 张齐（1 总览 + 3 分述）；总览「支持：」三项且与三张分述主题一一对应，未堆成能力清单
- [ ]（短文案）品牌 Tag 已加（中/英/俄按团队配置）
- [ ]（多语言）外文版走 native 语感非中译英，图上文字交 On-Image String Map（未声称能改 Figma）
- [ ]（发布）WP 版全篇无 emoji（含 ✅🚀），公告体结构：头图 + 导语 + 裸列表 + CTA，无小标题
- [ ]（发布）frontmatter lang / category 齐备（lang 缺则分类被重映射成英文），默认草稿未直发

## 示例

### 示例 1：视频脚本（30s · 摘要，全文见 references/example-launch-video.md）

功能：现货成本价　|　时长：30s　|　核心卖点数：3

- 开场·痛点钩子（0–3s）｜中文文案：「买了这么多，到底赚没赚，你算得清吗？」
- 功能一（3–9s）｜中文文案：「真实成本自动计算，不用手动对账。」
- 结尾·CTA（20–30s · Platform CLogo+二维码）｜中文文案：「看得见真实成本，算得准实际收益，立即打开Platform C App 体验！」

### 示例 2：短文案

```
## 标题
现货成本价上线：赚没赚，账替你算

## 中段

```

**好在哪**（对照「XX 功能全新上线！🚀」「一目了然」「清清楚楚」那种写法）：

- 标题「赚没赚，账替你算」是**分工**——把「算」这件事从用户手里拿走。后半句不是前半句的必然结果，是新信息。
- 「摊薄价旁边多一条线」是**对照**——跟产品里已有的那个东西并置，读者立刻知道自己会看到什么画面。换成任何功能都成立的「一目了然」，抽掉功能名照样通顺，所以它什么都没说。
- 「十几笔加仓减仓」是**具体场景**，不是「成本」这个抽象名词。
