# PRD Skill Eval 集

> 改 prd SKILL.md / 写作指南 / delta 骨架前后，用弱模型（非主力模型）各跑一轮对照，主力模型太强测不出规范的作用。
> 跑法：同一份输入材料 + 同一 prompt，新旧规范各跑 N 次；输出逐份人工读，再按下面的指标计数。
> 弱模型端点在 `.env` 的 `EVAL_*` 变量（Anthropic 兼容接口）。

## 输入材料

从一份已交付 delta 反推「PM 给模型的原始输入」：需求描述 + 会议结论 + 原型截图说明。不给原 PRD 正文。

- 任务 A：多变体组件（如社区 3.4.2 的盈利顶飘：合约 / 现货 × 普通用户 / 带单员）
- 任务 B：单模块含状态流转（如直播 2.4 的策略卡推卡 / 收回）
- 任务 C：补丁包（三到五条互不相关的小修）

## 指标

| 指标 | 怎么数 | 目标 |
| :--- | :--- | :--- |
| 篇幅 | §2 + §5 + §6 的字数（去 HTML 标签） | 比旧规范减半，且信息不丢 |
| 参数重复 | 每个阈值 / 次数 / 时长在全文出现的次数，取最大值 | 每个数字只出现一次 |
| 前后矛盾 | 同一件事两处写法不一致的条数 | 0 |
| 编造 | 输入里没有、被写成确定规格的机制 / 数值 | 0（应进「待确认」） |
| 信息覆盖 | 输入里每条业务规则在 PRD 里能找到 | 100% |
| 冷读可开工 | 干净子代理按 `cold_read.py` 探针读，「开工前要问」条数 | 越少越好，与旧规范对比 |
