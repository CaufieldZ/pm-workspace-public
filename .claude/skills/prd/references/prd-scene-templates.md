## 四、子场景模板（按场景类型选）

> **左图右文无条件铁律**：UI 场景只要有图，就用左图右文（带表头的原生 HTML `<table>`，左列图 + 右列三段式），**不分单端 / 双端 / bullet vs 编号**。生成器 `gen_prd_skeleton.py` 已按此吐好 `<table>` 骨架，PM 只填占位符。
> - 双端散件：左列上下双图（App 上 / Web 下），右列原文
> - 单端散件：左列单图（App / Web / CMS 任一），右列原文
> - 「一端有图、另一端跳外站没图」**仍按单端左图右文走**，不要把"另一端没图"当成不用左图右文的理由
> - 文字结构（bullet vs 编号）不影响左图右文选择；原文是 bullet → 按 D-2 / B-1 风格重组为「显示逻辑 / 显示要素 / 交互」三段式
> - 数据影响 / 异常场景 / 视角对比表留在 `<table>` **外**全宽展示

子场景分两类，模板不同：**UI 场景**（有图、页面分块明确）走「区块表版」；**横切策略 / 后端流程**（无 UI 或 UI 是别人的）走「粗体段版」。

> **delta UI 场景走三列规格表（图 / 规格 / 验收）**，见 §4.0；baseline / 完整 12 章 PRD 的 UI 场景仍走下方 §4.1 两列左图右文。两模板共存，按文档类型选。

### 4.0 delta UI 场景模板（三列规格表 · delta 默认）

适用：**delta PRD 的 UI 场景**。`gen_prd_skeleton.py --profile delta` 已自动吐三列 `<table>` 骨架，PM 填占位符即可。

**结构**：场景块 = 现状 + 修改点 + 三列规格表 + 跨模块/全局 + 异常场景 + 整体验收。

- **现状**：一句话，从什么变（引 baseline 现状，锚场景编号）。
- **修改点**（取代旧「本轮」标签）：一句话定向「现状 X → 变更 Y」，**不罗列规格**——规格全在下方表。
- **三列规格表**（`scene_block_card(spec_rows=[...])`）：每屏一行，列 = 示意图 / 规格（页面元素 + 字段·状态）/ 验收。
  - **规格列**：页面元素 + 字段/状态变更合一列（同是研发读，UI 长啥样 + 背后字段怎么存是一件事的两面）。支持一层嵌套 bullet（`(父, [子...])`），如「二选一 →〔TRTC / OBS〕」。
  - **验收列**：仅写**这一屏能勾的**判定点（做 X → 观察到 Y），与规格行对齐。能从规格图直读的（有 X 字段、显示 Y）不写。
  - **埋点不进表**：埋点是神策外部契约、有专门 10 列表，全集中到 §7，规格表连提都不提。
- **跨模块 / 全局**（取代旧「边界」标签）：表画不出的——跨模块联动、全局规则、遗留数据迁移、待拍项。「边界」筐废弃：真规则进此段或表，scope 排除进「不做」。
- **不做**：本轮明确不碰的 scope（仅有排除项时出现，非每场景必有）。
- **整体验收**：跨行 / 反向态断言（塞不进单屏的，如"放开后 X 不再被拦截"）。

**为什么三列**：行对齐——研发看规格 build、QA 看验收测，同一屏横向并排，同一事实只出现在一个格子，从结构上根除「本轮/表格/验收三处复述」的废话。

### 4.1 UI 场景模板（默认 · 推荐）

适用：列表 / 表单 / 弹窗 / 详情页 / 入口导航等有截图且页面分块明确的场景。**研发主消费**，结构按 UI 物理分块组织信息。

**默认模板：左图右文 = 带表头的原生 HTML `<table>` + 嵌套编号三段式**

> ⚠️ **新写 PRD 强制用本模板** — `gen_prd_skeleton.py` 骨架已自动吐好这个 `<table>`，PM 只填 `{{ 待填 }}` 占位符里的文字，**不要手改 `<table>` 结构、不要回退到下方 4 列区块表**。老 PRD（继续用 `:::leftright` 围栏的）维护时可沿用原样，迭代时自然转 `<table>`。

```markdown
### 5.1 A-1 · 【场景白话名】

**业务故事**：（≤ 30 字，讲谁 / 做什么 / 为什么）

<table>
  <colgroup>
    <col style="width: 30.0%;" />
    <col style="width: 70.0%;" />
  </colgroup>
  <thead>
    <tr>
      <th>示意图</th>
      <th>页面元素 &amp; 规则</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        <img src="./assets/scene-a1.png" alt="截图 alt" />
      </td>
      <td>
        <strong>1. 顶部 XX 栏</strong>
        <ul>
          <li><strong>显示逻辑</strong>
            <ul>
              <li>什么时候显示 / 不显示，权限 / 数据源 / 灰度规则（后端关心），一条一 bullet</li>
            </ul>
          </li>
          <li><strong>显示要素</strong>
            <ul>
              <li>字段 / 控件 / 文案逐项列（前端关心）</li>
            </ul>
          </li>
          <li><strong>交互</strong>
            <ul>
              <li>点击 X → 跳 Y / 触发事件 Z（前后端关心）</li>
            </ul>
          </li>
        </ul>
        <strong>2. 下一个区块名</strong>
        <ul>
          <li><strong>显示逻辑</strong>
            <ul>
              <li>...</li>
            </ul>
          </li>
        </ul>
      </td>
    </tr>
  </tbody>
</table>

**数据影响**

- 业务语言描述数据 / 状态变化，3-5 行 bullet（不写 SQL / 事件 key / API 端点）

**异常场景**

| 触发条件 | 系统响应 | 用户感知 |
| :--- | :--- | :--- |
| xxx | xxx | xxx |
```

**为什么这样设计**：

- **左图右文 = 带表头 HTML `<table>`**：研发对照截图 + 文字阅读，定位某区块不用滚来滚去；`md_to_confluence.py` 用 markdown-it 渲染成原生 storage `<table>`（左 `<ac:image>`、右嵌套 `<ol>/<ul>`），带「示意图 / 页面元素 & 规则」表头，Confluence 上可视化编辑单元格 + 往返回流（`fetch_confluence.py` pandoc 模式拉回零丢失）。
- **嵌套编号 + 三段式映射研发分工**：
  - **显示逻辑** → 后端（接口要不要返数据 / 权限边界 / 灰度规则）
  - **显示要素** → 前端（控件清单 + 文案）
  - **交互** → 前后端（事件触发 + 路由）
- **markdown 嵌套编号**：source = wiki 渲染 1:1，AI 读 source 看到的就是 wiki 形态，零转换损失。Confluence 自动按层级转 `1./a./i.`。
- **单一组件 vs 多分块判定**：一张卡 / 一个弹窗 / 一个 Toast 这种**单一独立 UI 元素**，不拆模块，直接整体三段式（不要为了模板套用机械拆顶部 / 中部 / 底部）；多分块页面（直播间整体 / 浮层含双 Tab / MGT 后台 + 表单）按 UI 物理分块拆模块。

**反模式告警 · 模块 ≠ 业务规则挂钩**（2026-05 复盘教训）

模块是 **UI 物理分块**（顶部栏 / 主体区 / 底部 sticky / 浮层），不是业务规则的收纳抽屉。下列内容**禁塞**成模块：

- **跨场景业务规则**（「三入口状态共享」/「N 计数口径」/「推送内容分流」/「关注 vs 订阅独立」）→ 写 §4，场景里「显示逻辑」一句「按 4.x 白话名」引用
- **决策备忘 / 理由段**（「为什么落战绩 TAB 不落内容 TAB」/「为什么用抽屉不用弹窗」）→ 决策归 delta §6 决策记录，PRD 不重抄
- **「通用文案」/「推送文案统一规则」**（8 类 toast 文案矩阵）→ 写 §8 通用文案清单，场景里不整段抄
- **纯分工说明**（「社区做什么 / 牛人榜做什么」）→ 可保留为独立段但不塞模块，否则 `显示要素：无 / 交互：无` 的空模块即废话

判定：写完一个模块回头看，如果「显示要素」为空 / 「交互」为空 / 或三段都是抽象业务规则（没有任何 UI 元素引用）→ **这不是 UI 模块**，压到上一个模块显示逻辑的一句引用，或整段挪到 §4。

「显示要素：无 / 交互：无」组合 = 空模块，必须删。

- App 单一组件：`livestream/archive/2026Q2/q2-update/.../audience-C-1-策略卡展示.md`（整体三段式不拆）
- PC 后台横图：`growth/activity-center/.../back-M-1-活动列表.md`（5 模块）
- 横切流程（套 :::leftright 但右列保留步骤式）：`livestream/archive/2026Q2/q2-update/.../audience-B-连麦全流程.md`

### 4.2 横切策略 / 后端流程模板

适用：无 UI 截图、或 UI 是别人的、本场景讲业务规则 / 后端自动行为 / 跨系统协议（如 M-7 自动同步、M-8 语种规则、E 信息架构）。

```markdown
### 6.5 M-7 · 【场景白话名】

**业务故事**：（≤ 30 字，讲谁 / 做什么 / 为什么）

**主题分块 1（如「自动同步范围」）**

- bullet（详细规则）

**主题分块 2（如「同步规则」）**

- bullet

**数据影响**

- bullet

**异常场景**

| 触发条件 | 系统响应 | 用户感知 |
| :--- | :--- | :--- |
```

**为什么不强行用区块表**：横切策略本质是「业务规则联合」不是「页面分块」，强表格会丢逻辑结构（如「自动同步范围」表 + 「同步规则」段 + 「特殊处理」段 三种异质内容塞一表会乱）。

### 4.3 模板的硬约束（两类共用）

- **业务故事**用 `**业务故事**：` 粗体引导一句话（禁 `>` 引用块 —— Confluence blockquote 渲染丑，全局禁用，`chapter_story()` 已落地此形式）
- **截图无 caption**（左图右文模板）—— `<table>` 左列 `<img>` 直接放，**不要再贴 `*斜体 caption*` 行**。前置语境（登录态 / 灰度规则 / Phase 区分）放对应模块的「显示逻辑」里，不重复
- **「异常场景」表**结构锁定 3 列：触发条件 / 系统响应 / 用户感知，名字不许变（旧版 `触发 / 响应 / 感知` 简写禁用）
- **「数据影响」**保留独立段（**放 `<table>` 外，全宽**），用业务语言不写技术实现（详见 4.4）
- **跨场景引用**用 `详见 白话名「编号」` 形式（如「详见 在线观众面板「A-2」」），编号在全角直引号内才被 PRD 自检豁免；裸编号「详见 A-2」会被 `bare_scene_codes` checker fail
- **左图右文 `<table>` 内嵌图片**仅左 `<td>`，右 `<td>` 只放结构化文字（`<strong>` 模块名 + `<ol>/<ul>`）；左右列宽由 `<colgroup>`（30% / 70%）控制
- **显示要素 / 交互一条一原子事实**：每个 `<li>` 一件事、短句（句段 < 100 字），多条拆成多个 `<li>`，**禁 `；` 串多条**（`；` 串是 §4.3.2 老区块表专属、左图右文 `<li>` 不 auto-split，串了在 wiki 上糊成一堵墙）。`check_prd_md.sh` 的分号滥用 / 长句 run-on WARN 兜底，交付前清零
- **三段式标签做组头，规则缩一级**：显示逻辑 / 显示要素 / 交互 在区块内各出现一次（`<li><strong>标签</strong><ul>…</ul></li>`），具体规则一条一 bullet 挂组头下；禁逐条 `<li>` 重复「显示逻辑：」前缀平铺一列（行形状检查各自单行都合格抓不到，`label_li_runs` WARN 专查：同一标签 ≥ 3 条连排即报）
- **不再写**：「前置条件」段、「用户看到」段、「本场景文案」段、「页面结构 & 信息层次」段。这 4 段在旧 8 段式里普遍冗余 / 与其他段重复，研发反馈砍了更清晰

### 4.3.1 异常场景表的 4 不写

异常场景表只写「场景独有 + 社区可控」的 1–3 条，写过头被判定为「用力过猛」。共性 / 边界外项一律上提到 §4 全局业务规则下的「全局异常降级总则」节，场景文件加一行豁免注释带过：

```
**异常场景**（接口超时、X 翻态延迟按 4.x 全局异常降级总则处理）

| 触发条件 | 系统响应 | 用户感知 |
| ...
```

**4 不写**（写了就是用力过猛，触发回炉）：

| 不写 | 例子 | 为什么 |
| :--- | :--- | :--- |
| ① 跨场景共性 | 接口超时 / 网络中断 / 缓存兜底 / 全站 IM 重试 / 三个月窗口外打点 / 翻态延迟 | 这是全局降级总则，写一次即可；每个场景重抄 N 遍只让 PRD 膨胀，不增加信息 |
| ② 全站规则继承 | 未登录 / 禁言 / 浏览器加载失败 / 多人编辑乐观锁 / 老版本 APP 兼容 | 沿用业务线（社区 / 直播 / CMS / 用户中心）现状，本期不重新定义，写在场景里只是噪音 |
| ③ 承载方边界外 | 「下单组件内部异常由合约组处理」/「IM 消息层延迟由 IM 团队定」/「Apollo 配置中心异常由配置中心兜底」 | 边界已在场景首段或业务规则里说明，重复列举只是为了凑表格行数 |
| ④ 没做的 UI 形态 | 骨架屏 / 下拉重试 / 黄色顶部 toast / 数字旁 loading 转圈 / 弹窗按钮文案逐字 | UI 实现归设计稿 + design system，PRD 写「占位 / 提示 + 文案要点」即可。原样写出来既约束了视觉决策，又随时被设计推翻成废话 |

**两不写**（保留场景独有项时的措辞约束）：

- 系统响应 / 用户感知列**不写具体文案**（如「吐司『请稍后重试』」），写「提示用户重试 / 提示发布失败」即可——具体措辞归 §8 通用文案清单
- 不写「重试 1 次仍失败 → 告警 + 人工介入」类 SLA / 监控决策，归 §10 非功能 + §11 监控告警

**判定流程**：写完异常表回头看每行，依次问：
1. 这条是不是已经在 §4 业务规则 / 全局降级总则 / 时间冲突校验矩阵里了？是 → 删
2. 这条是不是别的团队（合约组 / IM / 配置中心 / CMS）的内部异常？是 → 删
3. 这条系统响应是不是写了 UI 实现细节（骨架屏 / 黄色 / 倒计时悬停）？是 → 改成「占位 / 提示 + 文案要点」
4. 删完只剩 0 条 → 写一句「本场景无独有异常项，按 4.x 全局降级总则处理」收尾

实战参考：`community/base/prd-proj-community-v5.md §4.1 全局异常降级总则` + `community/base/prd-proj-community-v5-scenes/front-A-1-首页-Feed-流.md`（精简后只剩 2 条）；`livestream/archive/2026Q2/q2-update/deliverables/prd-livestream-q2-v3.1.md §8.8` + `audience-A-2-在线观众-打赏榜.md`（精简后整表删除）。

### 4.3.2 区块表 cell 多条规则用「；」串（不用 `<br>` / 不用 bullet）

> ⚠️ **`；` 串约定只适用老 4 列区块表**（md_to_confluence 按 `；` 切 bullet）。**默认的左图右文三段式（§4.1）不 auto-split**——显示要素 / 交互 `<li>` 里 `；` 串多条会在 wiki 上糊成一堵墙。左图右文模式一条一项写多个 `<li>`，别把区块表的 `；` 习惯带过去。

区块表「元素 + 规则」cell 同区块多条规则时，源文件直接用全角分号 `；` 串成一句即可。**不要在 source 里写 `<br>` 或手敲 bullet**——`md_to_confluence.py` 推 wiki 时会自动识别区块表头（4 列：区块 / 元素 + 规则 / 文案 / 数据来源），把 cell 整段切走转成原生 storage `<table>` + `<ul><li>` 渲染（每个 `；` 切一个 bullet）。

为什么不用 `<br>`：Confluence Markdown 宏在 cell 内不解析 `<br>` / `<ul>`，会当字面量显示为 `xxx<br>yyy`。

source 写：

```markdown
| 主舞台 | 拉流方式按版本路由：新版 TRTC（≤ 1s），老版 CDN（≤ 3s）；TRTC 失败自动降级 CDN；双击触发点赞动效（详见点赞场景）；灰度期 5% TRTC + 95% CDN | — | TRTC SDK / CDN |
```

wiki 渲染：

```
| 主舞台 | • 拉流方式按版本路由：新版 TRTC（≤ 1s），老版 CDN（≤ 3s）  | — | TRTC SDK / CDN |
|        | • TRTC 失败自动降级 CDN                                     |   |                |
|        | • 双击触发点赞动效（详见点赞场景）                          |   |                |
|        | • 灰度期 5% TRTC + 95% CDN                                  |   |                |
```

判定边界（自动渲染只触发于）：表头精确匹配 `| 区块 | 元素 + 规则 | 文案 | 数据来源 |`。其他普通表（§3.3 状态枚举 / §11 埋点等）继续走 markdown 宏，cell 内 `；` 不会被切。

### 4.4 数据影响的写法（重点）

用**业务语言**描述数据变化，不写 SQL / 事件名 / 表名：

- ✅ `新增一条帖子记录`（研发 AI 推 `INSERT INTO posts`）
- ✅ `用户发帖数 +1`（推 `UPDATE user_stats SET post_count = post_count + 1`）
- ✅ `通知关注该用户的订阅者`（推 `post.created` 事件 + 消息推送）
- ❌ `INSERT INTO posts (id, author_id, content) VALUES (...)`
- ❌ `发送 post.created(post_id, user_id, ts) 事件`
- ❌ `调用 /api/v1/posts POST 接口`

真要定死的字段（埋点事件 / 跨系统协议字段）**统一写在第 9 章业务事件清单**（PM 写业务事件 + 触发 + 业务字段 + 漏斗，事件 key 由数据团队按 naming convention 起，详见 §三点八「埋点章节的边界」）。

### 4.5 可断言规则形式（给定 ｜ 当 ｜ 则 · 可选档）

含条件分支的业务规则改用「给定 ｜ 当 ｜ 则」三列表，让下游（研发 / 测试 / AI 编码）拿到**条件→结果唯一可断言、分支可穷举**的规格，治两类下游缺陷：歧义（一句散文读出多解）、遗漏（边界 / 异常 / 空态没写，下游各自脑补）。形式对齐 §3.3 状态迁移表（起始 / 触发 / 终止），不是新发明。

```markdown
| 给定（前置态） | 当（触发 / 条件） | 则（预期结果） |
| :--- | :--- | :--- |
| 战绩私密（默认） | 用户在设置开启「公开」 | 战绩 TAB 实时对所有人可见；下次 Feed 重算进推荐池（非实时）；次日榜单刷新纳入 |
| 战绩公开 | 关闭「公开」 | TAB 实时仅自己可见；下次重算退出推荐池；次日移出榜单 |

边界 / 异常（必须穷举）：无历史交易数据用户开公开 → TAB 空态「暂无战绩」、不进推荐池（无数据不召回）
```

**何时用**（任一）：规则含条件分支 / 阈值档位 / 多业务态 / 状态迁移 / 多态显示逻辑。

**何时不用**（防臃肿）：无分支的纯陈述规则（如「关注与订阅语义独立」）保持 bullet，**别套壳**——可断言形式是可选档，不是所有规则都上表。

**穷举纪律**（治遗漏）：「当」列必须覆盖所有枚举值 + 阈值区间 + 空态 + 异常态。漏一个分支 = 遗漏。

**机械兜底**：`check_prd_md.sh` 对全局业务规则章（§4 / delta §5）单行 ≥ 2 个分支起始标记（若 / 如果 / 一旦 / 否则 / 反之 / 超过 / 低于 / 达到 / 不足）的散文 bullet 报 `branch_prose_hits` WARN，提示改可断言表。WARN 不阻断，纯陈述误报手动忽略即可。表格行 / 标题豁免——上了三列表自然清零。

> 同 §3.3 状态机：此三列表 cell 内 `；` 串多条**不 auto-split**（它不是 §4.3.2 的 4 列区块表），一条结果一项时拆 bullet 或编号，别糊成墙。

### 4.6 叶子完整性自查（7 类盲区 · 写作前移检查点）

> **这是冷读反测 7 类盲区的唯一权威定义**。`cold_read.py` 探针、prd SKILL.md「交付前冷读」Step 都引这一节；脚本里的探针问法是同一套类目的代码表达，不另立定义。
>
> 机械 7 维校验（编号 / 术语 / 跳转 / 字段格式…）抓的是「形」，叶子完整性抓的是「实」——一句话语法没毛病、字段都列了，但**读者要脑补才能落地**的语义缺口。写字段表 / 场景卡 / 状态机 / 全局规则时对照下面 7 类，问每条「我写死了吗，还是留给下游猜」。

| # | 盲区类别 | 要逼问的 | ❌ 反例（留洞） | ✅ 正例（堵洞） |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **时机 / 触发 / 周期** | 动态字段的刷新触发点、查一次 vs 持续、轮询间隔、定时节奏 | 「当前价基于实时市场价计算」（多久刷一次？进卡刷一次还是持续？） | 「当前价跟随行情持续刷新，详情卡每 N 秒拉一次，Feed 极简卡不刷只取发布时值」 |
| 2 | **字段生命周期** | 快照 vs 实时、发布即冻结 vs 跟随行情、翻态后旧字段锁不锁 | 「快照字段：分享时落库」（翻态 / 下线后还刷不刷？） | 「现货卡快照字段发布时一次性落库，此后永不刷新；翻态不影响」 |
| 3 | **边界 / 默认 / 空值** | 阈值端点含不含、默认值、空态 / 首次 / 离线 / 超期表现 | 「持仓 < 30 分钟走固定窗口」（恰好 30 分钟走哪档？无成交怎么办？） | 「< 30 分钟（不含）走 1m；空仓 / 无成交流水显示『暂无数据』占位」 |
| 4 | **跨位置定义一致性** | 同一概念多章口径是否打架、读者要横跳几处才拼得全 | A 章「仓位同步 SLA ≤ 5 分钟」+ B 章「翻态查询时发生」（读者误推翻态也有 5 分钟 SLA） | 两处都点明「SLA 仅约束字段值同步，holding→closed 翻态是查询时惰性翻转、无 SLA」 |
| 5 | **状态全集穷举** | 状态机漏态、自环（同态字段刷新）、离线再上线、并发 | 状态机只画 holding→closed，漏了 holding 内调杠杆的自环 | 补「holding —调杠杆/加减仓→ holding（字段刷新）」自环行 |
| 6 | **分支穷举** | 否定面 / 边界面、每个「当 X」是否有「当非 X」 | 「白名单内可发卡」（非白名单点了会怎样？前端拦还是后端拦？） | 「非白名单：发布器提交前前端校验拦截 + 后端兜底拒绝，提示不可发」 |
| 7 | **数据对齐 / 保留期** | 展示窗口 vs 底层保留期是否一致、超期降级、双数据源时间轴对齐 | 「K 线展示持仓全程」+ 「binlog 保留 3 个月」（超 3 个月的早期建仓点哪来？） | 「K 线窗口上限 3 个月与 binlog 保留期对齐，更早成交不打点、窗口锚定最近 3 个月」 |

**两个触发点共用这一套类目**：

- 写作前移：填字段表 / 场景卡时逐类自查（这一节即检查点）。
- 交付前冷读：`cold_read.py` 按这 7 类生成探针，干净子代理逐条反测（见 prd SKILL.md「交付前冷读」Step）。
