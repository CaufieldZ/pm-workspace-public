# 旧 12 章 PRD

只在 PM 明确要求写 12 章 PRD（不带 `--profile` 生成骨架）或维护现有 12 章 PRD 时读。delta 不用读本文件。12 章 PRD 也是一个 md 文件，场景再多也不拆。

## 一、12 章各写什么

| 章 | 写什么 |
| :--- | :--- |
| 1. 背景与目标 | 1.1 现状 / 1.2 价值 / 1.3 目标与成功指标 / 1.4 核心变更 / 1.5 用户角色与权限 |
| 2. 场景地图 | 2.1 场景编号表（从 scene-list 自动生成）/ 2.2 优先级 / 2.3 跨端数据流 |
| 3. 术语与业务对象 | 3.1 术语 / 3.2 本期新增的业务对象 / 3.3 枚举与状态机 |
| 4. 全局规则 | 两个以上场景共用的规则、归因规则、全局异常处理 |
| 5. 前台功能 | 一个场景一节：`### 5.1 A-1 · 发帖` |
| 6. 后台功能 | 同上 |
| 7. 跨端 / 后端 | 同上，无界面的写规则条目 |
| 8. 通用文案 | Loading / 空态 / Toast / 弹窗 / 错误文案 |
| 9. 埋点与看板 | 10 列事件表 + 看板口径（写法同写作指南第八节） |
| 10. 非功能 | 性能、一致性、生效时效、并发 |
| 11. 排期 | 阶段、依赖、后续规划 |
| 12. 附录 | 兼容矩阵、旧版差异，没有就写「无」 |

规则：

- 1–12 章章号固定，不跳号；某章没内容写「本期无」
- 5/6/7 章场景扁平，一个场景一个 `###`，不再往下嵌套 `####`
- 1.4 核心变更的基线是**当前线上**，不是上一版 PRD：线上没有这个功能就全部列为【新增】
- 3.2 只写本期新增的对象，线上已有的对象不出现、不重新定义
- 跨场景规则写一次在第 4 章，场景里写规则名；通用文案写在第 8 章，场景里只写本场景独有的文案

场景节的写法（有原型截图时）：

```markdown
### 5.1 A-1 · 发帖

（骨架生成的左图右文表：左列截图，右列按页面区块写规格，一条一件事）

**异常场景**（只写本场景独有的，没有就删）

| 触发条件 | 系统响应 | 用户感知 |
| :--- | :--- | :--- |
```
