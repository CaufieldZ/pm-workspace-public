# PRD 章节规则速查（写 PRD 前读这一页）

> 完整规则 → `prd-chapter-rules.md`。本文只留「写 PRD 时必守」的硬规则，细节 / 表格 / 例子见全量。

## 一、12 章结构（锁定，编号不能跳）

1 背景目标（1.1 现状 / 1.2 价值 / 1.3 目标+指标 / 1.4 核心变更 / 1.5 角色权限）· 2 场景地图 · 3 术语与对象词典（3.3 枚举+状态机）· 4 全局规则（4.1 跨场景 / 4.2 归因）· 5 前台 · 6 后台 · 7 跨端 · 8 通用文案 · 9 埋点与看板（9.1 事件 / 9.2 看板）· 10 非功能 · 11 排期 · 12 附录

- **子场景标题必带编号 + 白话名**：`### 5.1 A-1 · 发帖`；5/6/7 章禁两层嵌套（`##### N.x.y.z` 禁）
- **骨架章（1/2/3/4/8/9/10）禁 `>` blockquote 导读**（标题已表达的不复述）
- §1.6/1.7 可选章（模板在 prd-optional-sections.md）

## 二、迭代版 scope（铁律）

- **只写本轮真有改动的场景**；未动的整章删除，禁「本轮不动 / 同 V2 / 沿用线上」占位句
- **1.4 基线 = 当前线上运行版本**，不是之前的 PRD 版本。线上已有 → 列【变更】/【新增】/【本期不做】；线上没有 → 全部【新增】，标题保留「核心变更（本期全量新增）」
- 多轮决策迭代：1.4 收敛到最终态一行，迭代过程归 delta §6 决策记录

## 三、baseline vs delta（老项目迭代）

| 维度 | baseline | delta |
| :--- | :--- | :--- |
| 落点 | 产品线根 `prd-{线}-baseline.md`（无版本号） | `deliverables/{季度}/{版本}/` |
| 时态 | living 全量真相 | 单轮快照，上线反向合并 |
| scope | 全量（不删未动场景） | 只写本轮改动 |
| 1.4 / 里程碑 | 无 | 有 |
| 章节锚点 / 裸编号 | 允许 | 单文件允许；split 禁 |

- **delta 按产物形状切增量**：原子增量（独立场景/对象）→ 只写增量，插入 baseline 章尾；**结构整体**（权限矩阵 / 状态机全集 / 档位表 / 字段表）→ 写完整改后态 + 顶部「本轮改动：X→Y」callout，反向合并整块替换
- delta §2 按档位行文（`--tier`）：patch 走 §2.0 索引表收口（轻项表内讲完，重项才升 `### 2.N` 块）；feature 平铺叙事；bundle 强制索引表 + 单轴分组 H2。**轻项不起块**（现状=修改点否定式复述 / 跨模块元评论 / 「数据影响：无」都是噪音）
- **bundle 按端拆文件**（各端独立研发团队 + 开发明确要求时）：同版本号下产多个文件 `prd-{线}-{版本}-{端}.md`，每个文件独立完整（含 §1–§9），静态章只保留本端相关内容，原合并文件加废弃注释指向拆分后文件。

## 四、字段归属矩阵（避免跨章重复）

| 字段 | 跨场景共用 | 场景独有 |
| :--- | :--- | :--- |
| 业务规则 | 第 4 章（场景引「按 4.x 白话名」一句） | 场景块「显示逻辑」 |
| 状态机 | 3.3（场景引状态机） | 显示逻辑里的状态分支 |
| 文案 | 第 8 章 | 场景「显示要素」独有文案 |
| 数据字段 | 3.2 宏观 | 显示要素逐项（中文名 + 类型 + 约束 + 枚举） |
| 埋点 | 9.1 事件表（场景块连提都不提） | — |

**讲人话**：全文中文业务名（`主播 TRTC 标志｜布尔｜默认关`），不写 snake_case；唯一例外 = 埋点事件/属性英文名（神策契约）

## 五、编号 / 人话分层

- 场景编号只允许出现在：2.1 场景表左列 / 章节标题 / 截图文件名 / 埋点事件名
- **章节正文禁裸编号**，跨章引用用「见 5.1 发帖」式白话（`plain-language-gate` 兜底）

## 六、Confluence 渲染约束

- **禁 mermaid / PlantUML 源码块**（wiki 显示源代码）→ 表格 + 文字描述；流程 / 状态机表格四列：起点/终点/触发/延迟 或 起始状态/触发事件/终止状态/谁触发；≥ 8 节点走 flowchart skill 出 SVG 引用
- 禁 `>` blockquote（渲染丑）→ 粗体引导 `**业务故事**：`；禁 `---` 水平线；禁 `<details>`；禁 HTML 注释
- **PM 不写 URL / 路由**（`/activity-center` 禁，写「独立路由」业务语义）

## 七、PM 越界禁词 + 埋点

- 禁 JS 事件名 / DOM API / i18n / cache / modal / chip / 视觉细节 / px 值 / 技术变量名（hover / display:none / topicData...），完整清单在 chapter-rules §三点八
- **埋点 10 列模板**（所属页面/中文名/英文名/属性中文名/属性英文名/类型/必填/示例/平台/触发机制）；填表前必跑 `probe_event_properties.py` 拿真事件名
- 事件英文名前缀：`pageview_` 曝光 / `appclick_` / `webclick_` / `app_*_submit` / `cms_*`；命名 `{前缀}_{模块}_{动作}`
- **行内版本标签禁用**：表格/场景里禁「（新增）」「（变更）」，集中到 §1.4 列清单

## 八、章节 must-have（check_prd_md.sh 扫）

每章必须出现锚点：1（1.1-1.5）/ 2（2.1 编号表+2.3 数据流）/ 3（3.1-3.3）/ 4（4.1+4.2）/ 5-7（≥1 子场景且必含「业务故事」）/ 8（8.1-8.3 标题在即可）/ 9（9.1 表格+9.2）/ 10（SLA 表）/ 11（Phase）/ 12（标题在）

## 九、single vs split

- single（场景 ≤ 10）：单 md，≤ 1500 行；split（> 10）：主骨架 + `-scenes/` 子文件（`{view}-{编号}-{白话名}.md`，子文件内 h2 起）
- 编辑粒度（一场景一文件）≠ 推送粒度（一章一子页）；**跨子页章节号引用是死链** → 关键约束 inline 重述在子文件（容许少量重复）

## 十、图片约定

`./assets/scene-{编号}-{类型}.png`（wireframe/final/flowchart/screenshot）、DPI ≥ 144、alt 必须有

## 十一、交付前自检（check_prd_md.sh 通过后）

无裸编号（正文 grep `A-[0-9]` 等无命中）· 无 5 段式研发字段（`**触发/读/写/事件/API**`）· 图片路径有效 · CJK 标点过 · 无圈数字 · 术语无同义词 · 跨章引用带白话名
